# Contributing to Memori

We’re excited that you want to contribute to Memori! Whether you’re fixing a bug, adding a feature, improving documentation, or asking a question, every contribution helps make Memori better for everyone.

<Note>
  Want a zero‑setup option? Try Memori Cloud at
  [app.memorilabs.ai](https://app.memorilabs.ai).
</Note>

The Memori source code lives on GitHub at [github.com/MemoriLabs/Memori](https://github.com/MemoriLabs/Memori).

---

## Ways to Contribute

There are many ways to contribute to Memori — and not all of them involve writing code:

### Report Bugs

Found a bug? If Issues are enabled, open one on [GitHub](https://github.com/MemoriLabs/Memori/issues).  
If not, use [GitHub Discussions](https://github.com/MemoriLabs/Memori/discussions).

Include:
- A clear title describing the problem
- Steps to reproduce the issue
- What you expected versus what actually happened
- Your OS and Memori version  
  - Python: your Python version and `pip show memori`  
  - TypeScript: your Node.js version and `npm list @memorilabs/memori`

### Suggest Features

Have an idea for a new feature or improvement? Start a [GitHub Discussion](https://github.com/MemoriLabs/Memori/discussions) or open an enhancement issue (if enabled). Describe the use case and why it would be valuable.

### Improve Documentation

Documentation improvements are always welcome:
- Fix typos or unclear explanations
- Add new examples or use cases
- Improve guides for specific LLM providers or databases
- Translate documentation into other languages

### Contribute Code

If you’re ready to contribute code, follow these steps:

1. **Fork the repository** — Create your own fork of [MemoriLabs/Memori](https://github.com/MemoriLabs/Memori).
2. **Create a branch** — Branch off `main` with a descriptive name (e.g., `fix/streaming-bug` or `feat/redis-support`).
3. **Make your changes** — Write code, add tests, and update documentation if needed.
4. **Run the tests** — Ensure all existing tests pass and your new tests cover the changes.
5. **Submit a pull request** — Open a PR back to `main` with a clear description of what you changed and why.

See the [Development Setup](/docs/memori-byodb/contribute/development-setup) guide for instructions on setting up your local environment.

---

## Pull Request Guidelines

When submitting a pull request:
- **Keep PRs focused** — One feature or fix per PR.
- **Write descriptive commit messages** — Explain what changed and why.
- **Include tests** — New features should include tests; bug fixes should include a test that reproduces the bug.
- **Update documentation** — If your change affects the public API or user-facing behavior, update the relevant docs.
- **Follow existing patterns** — Match the style and conventions of the existing codebase.

## Code of Conduct

We are committed to providing a welcoming and inclusive experience for everyone.  
All contributors are expected to be respectful and constructive. Harassment, discrimination, and toxic behavior are not tolerated.

Please review the project’s Code of Conduct on the [GitHub repository](https://github.com/MemoriLabs/Memori) before contributing.
