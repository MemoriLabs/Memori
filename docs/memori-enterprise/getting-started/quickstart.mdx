# Quickstart

Connect the harness to your Memori Enterprise deployment through the Memori gateway. Before each prompt, Memori pulls in relevant memories. After each turn, the conversation is sent to your Memori server and processed into durable memories.

If your team routes harness requests through Amazon Bedrock, see [Bedrock setup](/docs/memori-enterprise/getting-started/bedrock) instead.

## Before you start

Gather these values before you begin.

<Properties>
  <Property name="ANTHROPIC_BASE_URL">
    Your company-specific Memori endpoint. Ask your admin for this value, such as `https://app.company-specific.memorilabs.ai`.
  </Property>
  <Property name="x-memori-entity-id">
    A lowercase identifier for the person whose memories this session should use. We recommend your LDAP username, such as `johnd`.
  </Property>
  <Property name="x-memori-identity-token">
    Shown in the Identities section of your Memori dashboard. Click the specific identity to copy this value.
  </Property>
  <Property name="x-memori-origin-id">
    Optional. A unique identifier for this workload. Use it when more than one system writes to the same Memori deployment and you want to track or filter memories by source. If you only have one harness deployment, leave this out. Ask your admin for the right value.
  </Property>
  <Property name="ENABLE_TOOL_SEARCH">
    Set to `true`. See step 3.
  </Property>
</Properties>

Store your identity token, entity ID, and base URL in a secure store such as your enterprise cloud key vault or a local password manager.

---

## 1. Set the variables

Add the following to `~/.claude/settings.json`. If `settings.json` already has an `env` block, add these keys inside it, do not add a second `env` block. If `ANTHROPIC_CUSTOM_HEADERS` is already set, add the Memori headers to the existing value, one per line.

```json
{
  "env": {
    "ANTHROPIC_BASE_URL": "PLACE_URL_FROM_ADMIN_HERE",
    "ANTHROPIC_CUSTOM_HEADERS": "x-memori-entity-id: johnd\nx-memori-identity-token: id_test_your_token_here",
    "ENABLE_TOOL_SEARCH": "true"
  }
}
```

If your admin has given you an origin ID, add it as a third header:

```json
"ANTHROPIC_CUSTOM_HEADERS": "x-memori-entity-id: johnd\nx-memori-identity-token: id_test_your_token_here\nx-memori-origin-id: your-origin-id-here"
```

In JSON, `\n` is a string escape, so the file holds those two characters and the harness receives a real newline between the headers.

Then restrict the file to your account, since it now holds the identity token:

```bash
chmod 600 ~/.claude/settings.json
```

## 2. Choose a scope

`~/.claude/settings.json` applies to every project on this machine. To scope to a specific project only, put the `env` block in that project's `.claude/settings.local.json` instead.

## 3. Set ENABLE_TOOL_SEARCH

A custom `ANTHROPIC_BASE_URL` makes some harness versions load every tool definition into the context upfront instead of on demand. Setting `ENABLE_TOOL_SEARCH` to `true` restores on-demand loading.

## 4. Restart the harness

Settings and environment variables are read when a session starts. Editing `settings.json` inside a running session has no effect. Quit the harness and start a fresh new session.

## 5. Check if it worked

Confirm your `settings.json` is valid JSON, then start the harness and have a short exchange. Open the Memori dashboard and check that memories are accumulating. On a new account the dashboard stays empty until a turn or two has been captured and extracted, so give it a couple of exchanges before concluding something is wrong.

<Admonition type="tip" title="Use the same entity ID everywhere">
  Use the same entity ID in every Memori client. A mismatched entity ID won't error, but memories will be created under the wrong entity and the dashboard will look off.
</Admonition>

## Troubleshooting

**Sessions work but no memories appear**

- Confirm the identity token matches the one shown in your dashboard.
- Confirm your entity ID matches the value used in other clients.
- Start a fresh new session after changing any value.

**Requests fail outright**

Double-check that `ANTHROPIC_BASE_URL` was entered correctly.

**Context is larger than expected**

Check that `ENABLE_TOOL_SEARCH` is set to `true`, per step 3.

---

## Uninstall

Remove `ANTHROPIC_BASE_URL` and `ANTHROPIC_CUSTOM_HEADERS` from everywhere you set them, then start a fresh new session. The harness goes back to the Anthropic API directly.
