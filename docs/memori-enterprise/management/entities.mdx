# Entities

An entity is the person that a memory belongs to. Every memory in Memori is associated with an entity: the facts, preferences, goals, and working context stored in Memori describe a specific person's history with Claude Code.

## What entities are for

Entity memory is private to each person. A Claude Code session configured with an entity ID reads from and writes to that person's memory only. No other entity's memory is accessible unless explicit pool access has been granted.

## Entity IDs

Each entity is identified by an entity ID: a lowercase string set during Claude Code plugin configuration with `/memori:configure`. Entity IDs can be any consistent identifier that maps to a person in your system, such as a username or email slug.

```
jane-doe
user_8472
```

## Consistency across clients

If a person uses Claude Code on multiple machines or has other integrations writing to Memori, use the same entity ID everywhere. A mismatched ID creates a separate memory space rather than contributing to the existing one. If memory recall looks incomplete, verify that all of a person's clients are configured with the same entity ID.

## Entity management

Owners and admins can view all entities in the organization from the Memori Enterprise dashboard. Entities are created automatically the first time a Claude Code session writes a memory under a given entity ID.

From the entity view, you can browse all memories attributed to an entity, delete individual memories, or delete all memories for an entity.

## Entity deletion

To delete all memories associated with an entity, including facts, session records, and knowledge graph nodes, use the SDK:

```python
from memori import Memori

mem = Memori()
mem.entity.delete(entity_id="user_123")
```

This is the correct path for responding to user deletion requests under GDPR and similar data protection regulations. The deletion is permanent and recorded in the audit log.
