# Entities

An entity is the person that a memory belongs to. Every memory in Memori is associated with an entity: the facts, preferences, goals, and working context stored in Memori describe a specific person's history with the harness.

## What entities are for

Entity memory is private to each person. A harness session configured with an entity ID reads from and writes to that person's memory only. No other entity's memory is accessible unless explicit pool access has been granted.

## Entity IDs

Each entity is identified by an entity ID: a lowercase string set during the harness plugin configuration with `/memori:configure`. Entity IDs can be any consistent identifier that maps to a person in your system, such as a username or email slug.

```
jane-doe
user_8472
```

## Consistency across clients

If a person uses the harness on multiple machines or has other integrations writing to Memori, use the same entity ID everywhere. A mismatched ID creates a separate memory space rather than contributing to the existing one. If memory recall looks incomplete, verify that all of a person's clients are configured with the same entity ID.

---

## Managing entities

### 1. Configure the entity ID

Set the entity ID during plugin configuration with `/memori:configure`. Use any consistent identifier that maps to a person in your system.

- Run `/memori:configure` in a harness session
- Enter the entity ID that identifies this user across your systems

### 2. Verify the entity in the dashboard

Entities are created automatically the first time a harness session writes a memory under a given entity ID. Owners and admins can view all entities from the Memori Enterprise dashboard and browse their memories to verify they are accumulating correctly.

### 3. Delete all memories for an entity

To delete all memories associated with a specific entity, including facts, session records, and knowledge graph nodes, use the SDK:

```python
from memori import Memori

mem = Memori()
mem.entity.delete(entity_id="user_123")
```

<Admonition type="tip">
  This is the correct path for GDPR right-to-erasure requests and similar data deletion requirements. The deletion is permanent, covers all memory records for that entity ID, and is recorded in the audit log.
</Admonition>
