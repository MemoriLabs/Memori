# Remove Memories

Memori provides several paths for removing memories, each with its own permission requirements. Understanding the difference between removing a memory from a pool and permanently deleting it from the memory bank is important before performing any removal.

## Removal vs Deletion

| Action | What it does | Who can do it |
| ------ | ------------ | ------------- |
| **Remove from pool** | Removes the memory from that pool only. The memory remains in the memory bank and in any other pools it belongs to. | Owners, admins, and users with pool remove-memories permission |
| **Permanently delete** | Removes the memory from the memory bank and all pools. Irreversible. | Owners only |
| **Delete all entity memories** | Removes all memories for a specific entity, including facts, session records, and knowledge graph nodes. | Owners, via the SDK |

All removal and deletion actions are recorded in the immutable audit log with the acting user and timestamp.

## Removing Individual Memories

To remove a memory from the Memory Explorer:

1. Navigate to **Dashboard → Memory Explorer**.
2. Search or filter to locate the memory.
3. Click the memory to open its detail view.
4. Select **Remove from pool** or **Delete permanently**, depending on your intent and permission level.

Owners see both options. Admins and users with remove-memories permission see pool removal only.

## Removing from a Pool

Pool removal is the appropriate action when a memory is no longer relevant to a specific pool's use case but should be preserved in the memory bank. For example, removing a customer-specific memory from a general knowledge pool while keeping it in the entity's private memory.

The memory remains in the memory bank and in any other pools it belongs to. Only the association between this memory and this pool is severed.

## Permanently Deleting a Memory

Permanent deletion removes the memory from the memory bank entirely. It is no longer accessible from any pool or through any recall query. This action is available to owners only and cannot be undone.

Use permanent deletion when a memory contains incorrect information that should not persist anywhere, or when a specific record must be removed to comply with a data subject request.

## Deleting All Memories for an Entity

To delete all memories associated with a specific entity, including facts, session records, and knowledge graph nodes, use the SDK:

```python
from memori import Memori

mem = Memori()
mem.entity.delete(entity_id="user_123")
```

This is the path for responding to user deletion requests under GDPR's right to erasure and similar regulations. The deletion is permanent, covers all memory records for that entity ID, and is recorded in the audit log.

See [Compliance](/docs/memori-enterprise/security/compliance) for more on GDPR and data subject rights handling.
