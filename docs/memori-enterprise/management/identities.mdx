# Identities

An identity is a programmatic client that interacts with Memori. The Memori Claude Code plugin runs as an identity: every Claude Code session that sends memories to your deployment authenticates with the identity ID configured during setup. Other integrations or applications that read from or write to your deployment also do so as identities.

## What identities are for

Identities give you access control over which integrations can read from or write to your deployment. Each identity has configurable pool access, and all of its operations are recorded in the audit log under its name.

## Identity IDs

Each identity has an identity ID that starts with `id_`. The identity ID is the credential an agent presents on every request. Identity IDs are created and managed in the Memori Enterprise dashboard under **Settings → Identities**. Treat identity IDs as secrets: store them in your secrets manager and rotate them on your credential rotation schedule.

## Creating an identity

Owners and admins can create identities from the dashboard. When creating an identity, you assign it a name used for attribution in the audit log and memory records, and configure its initial pool access.

## Pool access

Identities access memory pools through explicit grant, the same model as users. Open the pool from **Settings → Pools** or Memory Explorer, select **Add Identity**, and choose the identity.

**Write memories**: By default, an identity granted pool access can read memories from the pool. Enable this to also allow the identity to add new memories to the pool. Writes are additive; identities cannot remove or delete memories.

**Entity memory access**: When enabled, the identity can see entity memories when reading from this pool. Disable for identities that process requests for multiple customers and should not cross customer memory boundaries.

## Attribution

Every memory created by an identity is attributed to it in the audit log. The `process_id` field on each audit record contains the identity name. This attribution is immutable.

## Rotating identity IDs

To rotate an identity ID, generate a new identity ID from the dashboard and update the secret in your deployment. The old identity ID is invalidated immediately on rotation. Audit records written under the old identity ID retain their original attribution.
