# Identities

An identity is a programmatic client that interacts with Memori. The Memori Claude Code plugin runs as an identity: every Claude Code session that sends memories to your deployment authenticates with the identity ID configured during setup. Other integrations or applications that read from or write to your deployment also do so as identities.

## What identities are for

Identities give you access control over which integrations can read from or write to your deployment. Each identity has configurable pool access, and all of its operations are recorded in the audit log under its name.

## Identity IDs

Each identity has an identity ID that starts with `id_`. The identity ID is the credential an agent presents on every request. Identity IDs are created and managed in the Memori Enterprise dashboard under **Settings → Identities**. Treat identity IDs as secrets: store them in your secrets manager and rotate them on your credential rotation schedule.

## Attribution

Every memory created by an identity is attributed to it in the audit log. The `process_id` field on each audit record contains the identity name. This attribution is immutable: the record cannot be changed after the memory is written.

## Setting up an identity

### 1. Create an identity

Owners and admins can create identities from the Memori Enterprise dashboard. When creating an identity, assign it a name that will appear in the audit log and on any memories it writes.

- Navigate to **Settings → Identities** and select **New identity**
- Enter a name that identifies the integration or agent

### 2. Assign the identity to a pool

Open the pool from **Settings → Pools** or Memory Explorer, then select **Add identity** and choose the identity.

<Properties>
  <Property name="Write memories">
    Allow this identity to add new memories to this pool. Writes are additive; identities cannot remove or delete memories. Every new memory it writes is recorded in the audit log.
  </Property>
  <Property name="Entity memory access">
    Entity memories are facts about specific people and customers. When off, they're hidden from this identity. Recommended off for identities that should not access customer-specific information.
  </Property>
</Properties>

### 3. Configure the plugin

Store the identity ID in your secrets manager and configure the Claude Code plugin using `/memori:configure`. The plugin authenticates every session using this identity ID.

### 4. Rotate an identity ID

To rotate an identity ID, generate a new identity ID from the dashboard and update the secret in your deployment. The old identity ID is invalidated immediately on rotation.

<Admonition type="tip">
  Audit records written under the old identity ID retain their original attribution. Rotation does not affect historical records.
</Admonition>
