# User Role Assignment

User access in Memori Enterprise has two layers: organization membership and pool membership. Organization membership determines what a user can do across the deployment; pool membership determines which shared memories they can read or write.

## What it's for

Organization roles govern dashboard access and administrative capabilities. Pool membership is granted separately and controls which shared memory collections a user can see and interact with.

## Organization roles

Every user in Memori Enterprise is assigned one of three roles:

<Properties>
  <Property name="owner">
    Manage users, identities, domains, pools, and system settings. Permanently delete memories from the memory bank. Add themselves to any pool. Must be explicitly added to a pool to view its memories.
  </Property>
  <Property name="admin">
    Manage users, identities, domains, pools, and system settings. Remove memories from pools. Add themselves to any pool. Cannot remove owners from pools or permanently delete memories from the memory bank. Must be explicitly added to a pool to view its memories.
  </Property>
  <Property name="user">
    Access the dashboard. View memories within pools they have been explicitly added to. Cannot perform administrative actions.
  </Property>
</Properties>

## Pool membership

Pool membership is separate from organization membership and must be granted explicitly. No user is automatically added to any pool, including the pool creator. Owners and admins can add themselves to any pool.

## Permissions

Pool membership grants read access to the pool's memories. Two additional permissions can be granted per user when adding them to a pool.

---

## Managing user access

### 1. Invite a user

Owners and admins invite users through the Memori Enterprise dashboard. An invitation email is sent to the user; on accepting, they are added to the organization with the assigned role.

### 2. Update a user's role

To change a user's role after they have joined, select the user from the user list in the dashboard and update their role.

### 3. Add a user to a pool

Open the pool from Memory Explorer or pool settings, then select **Add user** and choose the user.

<Properties>
  <Property name="Remove memories">
    Allows this user to remove memories from this pool. The memory stays in the memory bank and in any other pools it belongs to. It does not delete it from the memory bank.
  </Property>
  <Property name="Entity memory access">
    Entity memories are facts about specific people and customers. When off, they're hidden from this user in this pool. Other pool access is unchanged. Recommended on for customer-facing roles.
  </Property>
</Properties>

### 4. Remove a user from a pool

- Owners can remove any user from a pool
- Admins can remove themselves or other admins, but cannot remove owners
- Users can remove themselves from a pool

<Admonition type="tip">
  Removing a user from a pool does not delete their contributed memories. It removes their ability to see the pool's memories and to write new ones.
</Admonition>
