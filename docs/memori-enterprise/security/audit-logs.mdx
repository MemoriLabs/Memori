# Audit Logs

Memori Enterprise records every memory operation in an immutable audit. Your security and compliance teams have a complete record of what happened, who did it, and when.

## Audit log

Every memory operation generates an audit event containing:

| Field | Description |
| ----- | ----------- |
| `timestamp` | UTC timestamp with millisecond precision |
| `operation` | The operation type (`capture`, `recall`, `delete`, `permission_change`) |
| `entity_id` | The entity whose memory was accessed |
| `process_id` | The agent or application that performed the operation |
| `session_id` | The session in which the operation occurred |
| `result` | Whether the operation succeeded or was denied |
| `denial_reason` | If denied: the access control rule that blocked the operation |
| `memory_ids` | The specific memory records affected |

### Immutability

Audit log records cannot be modified or deleted by Memori administrators or your team. The log is append-only and stored separately from operational data. For on-premises deployments, Memori provides guidance on write-once storage configuration to satisfy specific compliance requirements.

### Retention

Audit log retention is configurable independently of memory retention. Common configurations:

| Requirement | Retention period |
| ----------- | ---------------- |
| 90-day default | 90 days |
| 1-year HIPAA | 365 days |
| Indefinite | No automatic expiry; archive to cold storage on a schedule |

## Observability and telemetry

Memori Enterprise exports metrics and traces into your existing stack. Supported export targets:

- **OpenTelemetry (OTLP)**: Export traces and metrics to any OTLP-compatible backend (Datadog, Grafana, Honeycomb, Jaeger, and others)
- **Prometheus**: Scrape Memori's metrics endpoint directly
- **CloudWatch / Cloud Monitoring / Azure Monitor**: Available for VPC deployments on the respective cloud provider

### Key metrics

| Metric | Description |
| ------ | ----------- |
| `memori_captures_total` | Total memory capture operations |
| `memori_recalls_total` | Total recall operations |
| `memori_augmentation_latency_seconds` | Augmentation pipeline duration |
| `memori_recall_latency_seconds` | Recall query duration |
| `memori_access_denials_total` | Operations blocked by access control |
| `memori_entity_memory_count` | Memory count per entity |

### Traces

Memori emits OpenTelemetry spans for every operation in the capture and recall paths. Traces include:

- End-to-end latency for capture and recall
- Augmentation pipeline stages (extraction, embedding, storage)
- Access control evaluation
