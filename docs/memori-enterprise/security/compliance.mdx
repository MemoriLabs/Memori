# Compliance

Memori Enterprise is designed for regulated industries. Compliance controls, data residency, access governance, audit logging, and retention, are built into the architecture, not bolted on.

## What it's for

Enterprise deployments satisfy compliance requirements by keeping all memory data inside the boundary you control. Memori does not copy, cache, or index data outside that boundary.

## Certifications and standards

  </Property>

  </Property>
</Properties>

Contact Memori Labs to request documentation.

## Data residency

In Enterprise deployments, all memory data stays inside the boundary you control. For VPC deployments, the boundary is your cloud account. For on-premises deployments, it is your own hardware. Memori's compute also runs in the same region as your data.

If your compliance program requires data to stay within a specific geography, choose a VPC region or on-premises environment that satisfies the requirement.

## Encryption

All connections use TLS 1.2 or higher. Encryption at rest is managed by your infrastructure and cloud provider; Memori does not manage encryption keys. For key management requirements, we review your configuration during onboarding.

## GDPR: erasing an entity's memories

To delete all memories for a specific user in response to a deletion request:

```python
from memori import Memori

mem = Memori()
mem.entity.delete(entity_id="user_123")
```

This removes all facts, session records, and knowledge graph nodes associated with that entity. The deletion is permanent and recorded in the audit log.

<Admonition type="tip">
  Run this within your standard data subject request workflow. The audit log entry provides the evidence record your compliance team needs to document the erasure.
</Admonition>
