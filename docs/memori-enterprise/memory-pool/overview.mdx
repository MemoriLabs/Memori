# Memory Pools

A memory pool is a shared collection of memories that agents can read from and write to. Pools let you build knowledge that persists across users, teams, and workflows, separate from any individual user's private memory.

## What pools are for

Individual entity memory tracks what a specific user has said and done. Pools hold knowledge that belongs to the organization or a team rather than any one person.

## Creating a pool

Owners and admins can create pools. No role is automatically added to a pool at creation, including the creator. To access a pool's memories, the creator must add themselves explicitly, either by checking "Add creator to pool" during creation or by adding themselves afterward the same way they would add any other member.

## Writing to a pool

Pool memories are written and recalled the same way as entity memories. Recall can draw from both the pool and the requesting user's own memory in a single query.

## Permissions

Pool access is governed by the same ReBAC model. Each pool has its own access control list. Admins and users must be explicitly added to see a pool's memories.

## Setting up a pool

### 1. Create the pool

Owners and admins can create pools from **Settings → Memory pools**. Give the pool a name that identifies its scope.

- Navigate to **Settings → Memory pools** and select the + sign on the top right corner
- Enter a name and a description

### 2. Add users

Add each user who needs access from the pool's settings page.

- Open the pool and select Add a user from your organization

<Properties>
  <Property name="Remove memories">
    Allows this user to remove memories from this pool. The memory stays in the memory bank and in any other pools it belongs to. It does not delete it from the memory bank.
  </Property>
  <Property name="Entity memory access">
    Entity memories are facts about specific people and customers. When off, they're hidden from this user in this pool. Other pool access is unchanged. Recommended on for customer-facing roles.
  </Property>
</Properties>

### 3. Add identities

Grant identities access to this memory pool. Identities can read memories by default and can be given permission to write memories.

- Open the pool and select Add identity

<Properties>
  <Property name="Write memories">
    Allow this identity to add new memories to this pool. Identities cannot remove or delete memories. Every new memory it writes is recorded in the audit log.
  </Property>
  <Property name="Entity memory access">
    Entity memories are facts about specific people and customers. When off, they're hidden from this identity. Recommended off for identities who shouldn't access customer-specific information.
  </Property>
</Properties>

### 4. Verify

Check that the pool is receiving memories after a session ends.

- Open Memory Explorer and filter by pool name to see your new memories

<Admonition type="tip">
  Confirm that sessions assigned to this pool receive both pool memories and their own entity memories in recall.
</Admonition>
