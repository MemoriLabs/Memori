# Memory Pool

A memory pool is a shared collection of memories that agents can read from and write to. Pools let you build knowledge that persists across users, teams, and workflows, separate from any individual user's private memory.

## What pools are for

Individual entity memory tracks what a specific user has said and done. Pools hold knowledge that belongs to the organization or a team rather than any one person.

## Creating a pool

Owners and admins can create pools. No role is automatically added to a pool at creation, including the creator. To access a pool's memories, the creator must add themselves explicitly, either by checking "Add creator to pool" during creation or by adding themselves afterward the same way they would add any other member.

## Writing to a pool

Pool memories are written and recalled the same way as entity memories. Recall can draw from both the pool and the requesting user's own memory in a single query.

## Permissions

Pool access is governed by the same ReBAC model. Each pool has its own access control list. Admins and users must be explicitly added to see a pool's memories.
